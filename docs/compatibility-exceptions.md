# Compatibility exceptions

Ent Engine is based on three.js r187, which these docs call the reference, and keeps partial compatibility with
its API. This is every place where Ent observably differs from it, why, how it is tested, and what to change when
porting JavaScript code. Tests live in `packages/ent/test/compatibility/exceptions_test.dart`
unless noted.

| Id | three.js | Dart | Why |
|---|---|---|---|
| E-PRIVATE | `_x`, `_onChange()`, `_order` … are reachable from any JS code | Library-private: reachable inside `ent`, not from user code | Dart privacy is per library; the port is one library so upstream's own cross-class use (`Object3D` → `quaternion._onChange`) keeps working |
| E-NUM | One `number` type | `double` for values, `int` for indices, offsets, counts, hex colors, bit masks | Dart has two numeric types. Integer *literals* are accepted where `double` is expected; `int` *variables* need `.toDouble()` |
| E-UNDEFINED | `undefined` arguments and results | Optional nullable parameters; `null` where upstream returns `undefined` | Dart has no `undefined` |
| E-ITER | `*[ Symbol.iterator ]()` (`for…of`, spread) | `Iterable<double> get iterable` (`Iterable<Object>` for `Euler`, which also yields its order) | A vector cannot implement `Iterable`: its `length()` method and `min`/`max` clash with `Iterable` members |
| E-CLONE | `clone()` uses `new this.constructor()` and returns the subclass | `clone()` returns the declared class; subclasses override `clone()` | Dart has no constructor reflection outside mirrors |
| E-ARRAY | `toArray( array, offset )` writes holes or grows any array; reading past the end yields `undefined` | Growable lists are padded with `0.0`; writes past a fixed-length list are ignored (as a typed array does); `fromArray` past the end throws `RangeError` | Dart lists hold no holes or `undefined` |
| E-ERROR | `throw new Error( message )` | `throw EntError(message)`, same message, an `Error` subclass | No base `Error(message)` constructor in Dart |
| E-LOG | `console.warn( 'THREE.' + message, ...params )`; `setConsoleFunction( fn )` gets spread arguments | `print()` by default, with the prefix `ENT.` (upstream messages start `THREE.`); `setConsoleFunction` gets `(type, message, List params)` | No console in `dart:core`; Dart functions are not variadic. The TSL stack-trace enhancement of `warn`/`error` is not ported (no TSL nodes) |
| E-UNION | Duck-typed unions: `Scene.background` (Color\|Texture), `Scene.fog` (Fog\|FogExp2), `Mesh/Line/Points.material` (Material\|Material[]), geometry `shapes` (Shape\|Shape[]), Lathe points, `applyBoneTransform`/`getColorAt` targets, `Vector3.addScaledVector( Vector3\|Vector4 )`, `Vector4.copy( Vector3\|Vector4 )` (w = 1 for a Vector3), `Matrix3.makeTranslation( Vector2\|number, y )`, `Matrix4.makeTranslation/setPosition( Vector3\|number, y, z )` | `Object` parameter with a type test; same results for the upstream types; any other type throws `ArgumentError` | Dart has no union types |
| E-ARGS | Missing arguments are `undefined`: `new Matrix4( 1 )` stores `undefined`, `v.setLength()` computes NaN | Element arguments of `Matrix2/3/4(…)` are optional but must all be given once the first is (else a `TypeError`); parameters upstream always uses are required | `undefined` arithmetic has no Dart equivalent; such calls are bugs upstream too |
| E-FLAGS | Every object answers any flag: `new Vector3().isEuler` is `undefined` | A class has only its own and inherited flags; `isEuler` on a `Vector3` does not compile. `Object3D` declares `isCamera`/`isLight` (false), which subclasses override, because `lookAt` and others test them | Static typing; use `is Euler` for a foreign type |
| E-STATIC | `Triangle.getNormal( a, b, c, target )` static and `triangle.getNormal( target )` instance share a name (also `getBarycoord`, `containsPoint`, `getInterpolation`, `isFrontFacing`; `AnimationClip.toJSON( clip )` static vs `clip.toJSON()`; `MaterialLoader.createMaterialFromType`) | Statics get a `Static` suffix: `Triangle.getNormalStatic(…)`; instance methods keep the upstream names | A Dart class cannot declare a static and an instance member with the same name |
| E-OBJECT | Plain objects: `toJSON()` results, `color.getHSL( { h, s, l } )` targets, `Interpolant.settings`, `ColorManagement.spaces` entries, geometry groups, draw range, `updateRanges`, camera `view`, raycast intersections, `Raycaster.params`, `RenderTarget` options, data images `{ data, width, height, depth }` | `Map<String, Object?>` for JSON, settings, options, params and colour-space definitions (keys as upstream); small classes with upstream's field names for fixed shapes: `HSL`, `GeometryGroup`, `DrawRange`, `UpdateRange`, `CameraView`, `Intersection`, `DataImage` | No object literals in Dart; maps keep arbitrary keys where upstream code extends the objects |
| E-SINGLETON | `ColorManagement` is an object instance built by a factory | An `abstract final class` with static members: `ColorManagement.convert(…)`, `ColorManagement.enabled = false` read as upstream | A Dart name cannot be both a type and a value; there is one instance upstream too |
| E-CONSTOBJ | Object-valued constants (`MOUSE`, `TOUCH`, `TimestampQuery`, `InterpolationSamplingType`, `InterpolationSamplingMode`, `Compatibility`, `RenderObjectRefreshType`) are frozen objects | Classes of static constants: `MOUSE.LEFT` reads the same, but the object itself cannot be passed or iterated | Dart constants of anonymous object shape do not exist |
| E-INTNAN | `color.getHex()` with a NaN component returns a number computed through `ToInt32` | `int` result; a NaN or infinite component throws `UnsupportedError` | Dart `int` has no NaN |
| E-EVENT | Events are plain objects `{ type, ...data }`; listeners are called with `this` bound to the dispatcher | `Event(type, [data])` with `event['key']` for extra fields; `event.target` is the dispatcher during dispatch and `null` after; listeners are `void Function(Event)` matched by `==` | No object literals or dynamic `this` in Dart |
| E-PLATFORM | Browser globals: `performance.now()`, `document` visibility (`Timer.connect`), WebGL buffer handles, HTML images, video and HTML-element textures, WebAudio, DOM elements of `Controls` | Replaceable adapters: `performanceNow` (defaults to a `Stopwatch`), `TimerDocument`, `ImageUtils.platform` (`ImagePlatform`), `VideoTexture.platform`, `HTMLTexture.platform`, `AudioContext.platform` (the `WebAudio*` interfaces, plus `WebAudioDecodingContext` for `AudioLoader`), `Loader.platform` (`LoaderPlatform`: `fetch`, `createImage`, `createImageBitmap`, `createBlob`, `parseDocument`, `normalizeNFC`; pure-Dart `AbortController`/`AbortSignal`/`ProgressEvent`); `GLBufferAttribute.buffer` and `Controls.domElement` are opaque `Object?` handles | Core stays free of browser and Flutter dependencies; a web or Flutter package installs the adapters. Without an image platform, `ImageUtils.getDataURL` of a non-data image throws `StateError` |
| E-VARIADIC | `object.add( a, b, c )`, `object.remove( a, b )`, `new AnimationObjectGroup( a, b )` and its `add`/`remove`/`uncache` | One object per call for `Object3D`; a `List` for `AnimationObjectGroup` | Dart functions are not variadic |
| E-PROPERTY | `object[ name ]` reads and writes any property, including ones added at runtime (`PropertyBinding`, `getObjectByProperty`, `setValues`, `fromJSON`) | `operator []`/`[]=` over declared properties on `Object3D` and subclasses, `_getValue`/`_setValue` on `Material` and `Texture`; `null` for unknown names; no runtime-added properties (`fromJSON` drops unknown keys). `setValues` assigns `null` like upstream, except to a non-nullable Dart property, which keeps its value and warns. As in r187, tracks cannot bind `light.shadow.*` or `scene.fog.*` (`parseTrackName` only treats material, materials, bones and map as object names) | No dynamic properties on Dart objects. `getObjectByProperty` works through it |
| E-ATTRIBUTE | `geometry.attributes` may hold a `GLBufferAttribute` | `attributes` is `Map<String, BufferAttributeLike>` (BufferAttribute or InterleavedBufferAttribute, the types upstream's JSDoc declares); `GLBufferAttribute` is not accepted yet; `index`/`indirect` are `BufferAttribute?`, so `setIndex` takes a plain list or a `BufferAttribute` (a raw typed list, which upstream would store as-is, throws `TypeError`) | `GLBufferAttribute` has no data API to share; revisited with the renderer |
| E-CURVE | `Curve` returns `Vector2` or `Vector3` points depending on the subclass; the base `getPoint` warns and returns `undefined` | `Curve<T>` with `T` `Vector2` or `Vector3`; the base `getPoint` warns and returns `null`; `computeFrenetFrames` needs a `Curve<Vector3>` and returns a `FrenetFrames` record, `extractPoints` a `ShapePoints` record (upstream field names) | Static typing of the point type |
| E-FACTORY | `KeyframeTrack` interpolant factories are functions stored on the instance and called with `this`; loaders register classes (`ObjectLoader.registerMaterial( MyMaterial )`) | `createInterpolant()` over an `interpolantFactory` field of type `(track, result)`, so a factory copied by `clone()` binds to the new track; loaders take a constructor tear-off (`MyMaterial.new`) or a `fromJSON` function | No dynamic `this` |
| E-OBJTRACK | `StringKeyframeTrack`/`BooleanKeyframeTrack` interpolate arrays of strings or booleans with the discrete interpolant | `KeyframeObjectInterpolant` interpolates value indices and writes values into `objectResult` | Dart interpolants hold `double`s |
| E-ARRAYTYPE | `TimeBufferType`/`ValueBufferType` are constructors (`Float32Array`, `Array`) | Constructor names as strings (`'Float32Array'`, `'Array'`), resolved by `AnimationUtils.convertArray` | Dart has no first-class constructors for typed lists |
| E-EULERBIND | Binding a track directly to an `Euler` overwrites its order with a number (`Euler.fromArray` ignores the offset) | The order is kept | The upstream result is an invalid order string; the port does not reproduce it |
| E-STABLESORT | `Array.prototype.sort` is stable | Stable sorts where upstream depends on order (BatchedMesh, Raycaster, curves); a NaN comparison counts as equal, as in V8 | Dart's `List.sort` is not guaranteed stable |
| E-INFJSON | `JSON.stringify` writes `Infinity` as `null`; loading assigns that `null` (`MeshPhysicalMaterial.attenuationDistance`) | A `null` read back into a non-null `double` that defaults to `Infinity` becomes `Infinity` | Dart's field cannot hold `null`; `Infinity` is what the JSON lost |
| E-IO | `FileLoader` decodes any WHATWG charset label; `Cache.get` tells a stored `undefined` from a missing key; `LoadingManager.resolveURL` NFC-normalizes with `String.normalize` | Non-UTF-8 labels decode through `Encoding.getByName` (latin1 is ISO-8859-1, not windows-1252); `Cache.get` returns `null` for both; NFC goes through the loader platform | `dart:convert` has fewer codecs and no Unicode normalization |
| E-NAMESPACE | Module-level exports `clamp`, `lerp`, … in `MathUtils.js` | Only the `MathUtils` class with static members | Matches the public `three` entry point, which exports `MathUtils` only |
| E-SHADERS | `WebGLRenderer` builds GLSL per material at runtime (`#define`s, `ShaderChunk`, `onBeforeCompile`); `ShaderMaterial` and `RawShaderMaterial` take GLSL source | `FlutterGpuRenderer` uses shaders compiled ahead of time by `impellerc`. A material that draws a mesh, points or sprites (every kind but ShadowMaterial) draws with a fragment stage that is a variant of its kind, compiled at build time from the keys the app registers (`hooks: user_defines: ent_flutter: shaders:` in its pubspec, `docs/usage.md`, `docs/shader-variants.md`): its maps, physical layers, transmission, depth packing and polygon offset are `#define`s, as WebGLPrograms defines them (MeshStandardMaterial and MeshPhysicalMaterial share the kind `physical`). A draw whose variant is not registered throws a `StateError` naming its key; in recording mode (`recorded`) its key is recorded and the object is not drawn, with one warning. Upstream compiles any combination at first use. The environment map type, fog, tone mapping, lights and shadows stay uniform switches inside a variant, with fixed maximum light counts: 4 DirectionalLight, 8 PointLight, 4 SpotLight, 2 HemisphereLight, 2 RectAreaLight per frame (RectAreaLight lights MeshStandardMaterial and MeshPhysicalMaterial only and casts no shadow, as in r187; its LTC tables take texture slots 11 and 12 of those variants while the frame has one; AmbientLight and LightProbe are summed, no limit). Lights past a maximum are ignored (after upstream's ordering, shadow-casting first) with one warning per type (`FlutterGpuRenderer: more than 8 PointLights in the scene; ...`); upstream compiles a program for any count. Tested in `packages/ent_flutter/test/renderer_test.dart` (light maximums). Shadow maps and spot-light maps share a pool of 6 texture slots per frame (`maxLightTextures`); a light past it is dropped with one warning. The physical variants bind their 2D textures through 15 generic slots plus `env_map` (16 sampler states, the iPhone 11's A13 limit; `shaders/slots.glsl`): maps with the same texture and sampler share a slot, and a draw whose distinct textures (maps, light textures, DFG table, transmission target) exceed 15 throws a `StateError` naming the map that found no slot (tested in `renderer_test.dart`); upstream binds every map. Skinning reads upstream's float `boneTexture` (Skeleton.computeBoneTexture's layout) with `textureLod` at texel centres in place of `texelFetch`; no bone maximum. Morph targets read upstream's texel layout from a 2D float texture (targets stacked in rows, not a DataArrayTexture) with the influences in a uniform array of at most 64 (`maxMorphTargets`); targets past it are not drawn, with one warning. A SkinnedMesh with morph targets draws with the combined vertex stage. An InstancedMesh's `morphTexture` (setMorphAt) is read from a second vertex texture, the row `gl_InstanceIndex`. A draw binds at most 20 textures over both stages (at most 16 fragment ones, the bone and morph textures, an InstancedMesh's `morphTexture` and the displacementMap), within the 32 Flutter GPU binds, so a skinned, morphed or instanced draw keeps them all, with the widest variant too (tested in `renderer_test.dart`) | Flutter GPU loads only precompiled shader bundles (`ShaderLibrary.fromAsset`, `fromBytes`); there is no runtime shader compiler. The maximums keep the `LightInfo` block small (lights, then the directional, spot and point shadow members) |
| E-SHADERMATERIAL | `ShaderMaterial` and `RawShaderMaterial` take GLSL source that the renderer compiles at runtime, fed by `Uniform`, `UniformsGroup` and `UniformsUtils`; `Material.onBeforeCompile` edits a material's shader source before it compiles, `customProgramCacheKey` keys that program and `precision` sets its float precision; the built-in materials carry `defines` for their shaders (`MeshStandardMaterial`'s `STANDARD`, `MeshPhysicalMaterial`'s `PHYSICAL`, `MeshToonMaterial`'s `TOON`, `MeshMatcapMaterial`'s `MATCAP`) | Not ported: ent compiles no shader at runtime. Every material is a typed description and each renderer owns the shaders for the materials it supports (E-SHADERS; effects are typed materials too, E-POSTPROCESSING), choosing a program by the material's class, so no material has `defines` (the reference's MeshMatcapMaterial `defines` unit test is not ported). `MaterialLoader` and `ObjectLoader` read a `ShaderMaterial` or `RawShaderMaterial` in a scene file as a plain `Material`, with the unknown-type warning. Tested in `packages/ent/test/loaders/material_loader_test.dart`; the materials and loaders fixtures leave the two classes out (`tool/reference/js/materials.mjs`, `loaders.mjs`) | A design choice: Flutter GPU has no runtime shader compiler, and compiling at first use stalls frames; a renderer that could compile draws the same typed materials instead of a second, runtime path |
| E-BLEND | `CustomBlending` with `MinEquation`/`MaxEquation`, or with constant factors that read `material.blendColor` and `blendAlpha` (`gl.blendColor`) | `MinEquation` and `MaxEquation` blend as `AddEquation`; constant factors read Flutter GPU's blend constant, which cannot be set; one warning each | Flutter GPU 3.47.6 has no MIN/MAX blend operation and no blend-color state |
| E-MIPMAP | A mipmapped texture has log2(max(width, height)) + 1 levels, down to 1×1 | At most `Texture.fullMipCount(width, height)` levels (floor(log2(min(width, height)))): no 1×1 level, and fewer for non-square textures; past the last level the sampler stays on it (a 1-pixel quad samples the 2×2 level). Render targets too: the PMREM's source cube (256² faces) stops at 2×2, so the few GGX samples of PMREM levels 1 and 2 whose matched source level lies past 7 read level 7 (at most 5 of 256 samples, weighted by their NdotL); the transmission target (128² at the reference size) stops at 2×2, so a transmissive material whose lod (log2(size) × roughness × clamp(2 ior − 2)) exceeds 6 blurs less than upstream; a minified CubeTexture stops at 2×2 per face. Tested in `packages/ent_flutter/test/renderer_test.dart` | Flutter GPU 3.47.6 refuses more levels (flutter/flutter#186176) |
| E-DISTANCE | Drawing a `MeshDistanceMaterial` outside a point light's shadow map throws (`refreshUniformsDistance` reads `properties.get( material ).light`, set only by WebGLShadowMap) | Objects with it are not drawn, with one warning; `FlutterGpuRenderer.distanceLight` (visible for testing) supplies the light. Point light shadow maps do not use it: r187 samples their `CubeDepthTexture`, not the material's color, so the casters are drawn with the depth material. Tested in `packages/ent_flutter/test/renderer_test.dart`; the shader is checked by the `distance` reference scene | A thrown error in a frame is not useful behaviour to reproduce |
| E-SHADOWMAP | WebGLShadowMap renders each shadow into `shadow.map` (a `WebGLRenderTarget` with a `DepthTexture`) and samples it with a comparison sampler (`sampler2DShadow`, PCFShadowMap) or nearest filtering (BasicShadowMap); VSMShadowMap blurs into an RG half-float target | `FlutterGpuRenderer` keeps each map internally (`shadow.map` stays `null`): a 32-bit float color target holding the fragment's depth, drawn with a depth buffer, and the shader filters the PCF comparisons itself (four nearest texels per sample, weighted bilinearly, as the hardware does). Directional and spot lights; a point light's cube map is six faces side by side in one such target (one slot of the light texture pool), read through the GL cube map face table; under PCFShadowMap the shader reads a filtered sample's texels past a face's edge from the neighbouring face, as seamless cube sampling does (its scenes pass on Metal and are skipped under flutter_tester, docs/flutter-gpu.md). VSMShadowMap (directional and spot lights) blurs the depth into two RGBA half-float targets kept with the map (upstream RG half floats; one slot of the light texture pool); its scenes match r187 on Metal (0 wrong, 0 edge pixels) and are skipped under flutter_tester, where SwiftShader's spot map is 44 pixels off (docs/flutter-gpu.md); `customDepthMaterial` and `customDistanceMaterial` are not ported. Tested by the `shadow_*` reference scenes | Flutter GPU 3.47.6 has no comparison samplers, and a depth texture's sampling is not part of its API |
| E-BATCHING | WebGLRenderer draws a `BatchedMesh` with `multiDrawElementsWEBGL` (or one draw per range setting `_gl_DrawID`), its vertex stage reading the instance from `batchingIdTexture` and its matrix and color from `batchingTexture` and `batchingColorTexture`; batched shadow casters update their ranges in `onBeforeShadow` | `FlutterGpuRenderer` draws one range per draw call and resolves the draw id on the CPU: the range's instance matrix and color (read from the same textures' data) are per-draw uniforms (`BatchInfo`, shaders/mesh.glsl), so the three textures are never uploaded and the draw binds no extra texture; same pixels (`batched_basic`, `batched_colors`). Batched shadow casters take the same path in the shadow passes after `onBeforeShadow` (`batched_shadow`, `batched_shadow_point`) | Flutter GPU 3.47.6 has no multi-draw and no draw id; one range per draw needs no per-instance lookup |
| E-READPIXELS | `renderer.readRenderTargetPixels( target, x, y, w, h, buffer )` fills `buffer` synchronously (glReadPixels); `depthBuffer: false` renders without depth testing | `Future<void> readRenderTargetPixels(...)`: await it before reading `buffer` (same rows from the bottom, same bounds and type checks: 8-bit RGBA only). A target with `depthBuffer: false` still gets a depth buffer (one warning); `samples`, `count > 1`, stencil, `generateMipmaps` (of a 2D target) and 3D and array targets are ignored with one warning each; a `WebGLCubeRenderTarget` is drawn face by face (E-CUBECAMERA). With `scissorTest`, the clear still covers the whole target (a pass's load action, not `gl.clear` inside the scissor). Tested in `packages/ent_flutter/test/renderer_test.dart` and the `rt_*` reference scenes | Flutter GPU returns texture contents only through `Texture.asImage()` and `Image.toByteData()`, which are asynchronous |
| E-CUBECAMERA | `CubeCamera.update( renderer, scene )` takes the renderer; WebGLRenderer reports `coordinateSystem` WebGLCoordinateSystem, so the cube camera uses the WebGL orientation, and the target's texture is sampled without the x mirror (`isRenderTargetTexture`) | `update` takes a `CubeCameraRenderer` (the six renderer calls it makes); `FlutterGpuRenderer.coordinateSystem` is WebGPUCoordinateSystem (its clip space), so the cameras take the WebGPU orientation and the faces are stored as a CubeTexture's images, sampled with the x mirror (as WebGPURenderer's CubeTextureNode): the same texels. `render` into a cube face returns a 1 × 1 black image. The six faces share one depth buffer (upstream has one per face; only visible with `autoClear` false). `WebGLCubeRenderTarget.fromEquirectangularTexture` and `clear` are not ported (the renderer converts equirectangular maps itself). No WebXR or reversed depth buffer steps. Tested by `cube_camera_basic` and `cube_camera_standard` | Flutter GPU's clip space and texture rows are WebGPU's; Dart cannot call an untyped renderer |
| E-DECODE | The browser decodes images for WebGL with straight alpha (`UNPACK_PREMULTIPLY_ALPHA_WEBGL` false) | `FlutterImage` decodes a PNG with its own decoder (`packages/ent_flutter/lib/src/png.dart`, on another isolate) to the straight bytes as stored, as Chrome does (every color type and bit depth, tRNS, Adam7; 16-bit samples by their high byte, as Chrome; gAMA, iCCP and sRGB ignored, as with `colorSpaceConversion: 'none'`). Other formats (JPEG, WebP, AVIF where dart:ui decodes it) go through dart:ui, which premultiplies: a translucent texel's color may move by up to 255 / alpha steps and a transparent one loses its color, which only matters for WebP or AVIF with alpha. Tested in `test/png_test.dart` (fixtures from `tool/png_fixtures.mjs`, checked against Chrome) and `test/platform_test.dart` | dart:ui offers no straight-alpha decode |
| E-DOM-CONTROLS | `OrbitControls`/`MapControls` attach DOM listeners in `connect( element )` (`pointerdown`, `pointercancel`, `contextmenu`, `wheel` on the element; `pointermove`, `pointerup`, a capture-phase `keydown`/`keyup` for the Control key on its document; `keydown` on the element passed to `listenToKeyEvents`), capture the pointer, set `style.touchAction` and `style.cursor`, and read `clientWidth`, `clientHeight` and `getBoundingClientRect()` | The element is a `ControlsElement` (left, top, `clientWidth`, `clientHeight`, `cursor`, `touchAction` fields) that the platform keeps sized; the listeners are public entry points the platform calls (`onPointerDown`, `onPointerMove`, `onPointerUp`, `onPointerCancel`, `onMouseWheel`, `onKeyDown`, `onContextMenu`, `interceptControlDown`, `interceptControlUp`) with `ControlsPointerEvent`, `ControlsWheelEvent` and `ControlsKeyEvent` (the fields upstream reads; `preventDefault()` sets `defaultPrevented`); flags stand in for attaching and removing listeners, so each entry point acts exactly while upstream's listener would be attached (document `pointermove`/`pointerup` only while a pointer is down, `onKeyDown` only after `listenToKeyEvents`, nothing after `disconnect`). `listenToKeyEvents` takes a `ControlsElement`; `onContextMenu()` returns whether upstream would prevent the menu. | E-GLTF | `GLTFLoader` works with promises (`parse` chains `Promise.all`, `getDependency` caches promises); plugins are duck-typed objects; the parser picks `TextureLoader` or `ImageBitmapLoader` and passes `crossOrigin` to it; Draco, KTX2 and meshopt decode through the objects set with `setDRACOLoader`, `setKTX2Loader`, `setMeshoptDecoder` | Futures in place of promises (`parseAsync`, `loadAsync`; `getDependency` caches futures); plugins extend `GLTFLoaderPlugin`, whose hooks return `null` where upstream's method is missing; a material type is a constructor tear-off (`MeshStandardMaterial.new`, `GLTFMaterialType`). `parse` takes a JSON `String`, a `ByteBuffer` holding exactly the file, or the decoded map. Futures complete in another order than JS promises, which is visible only where upstream depends on it: with several scenes, each `loadScene` replaces `parser.associations` with its own scene's (r187 keeps the last scene to finish, so which nodes keep their associations differs; one scene is exact), and suffixes of duplicate mesh names follow completion order (the fixtures match). Futures also complete a chain depth-first where JS runs each promise callback as its own job: `loadTextureImage` configures its texture in a microtask, so the clones other textures of the same image take (`sourceCache`) see it before `assignTexture` changes it, as in r187. Part 2 (B5b): an image in a buffer view becomes a `data:` URI of its `mimeType` instead of a `Blob` behind an object URL (no `revokeObjectURL`); the parser takes the `ImageBitmapLoader` where `Loader.platform.hasCreateImageBitmap` (Flutter) and the `TextureLoader` otherwise (upstream also checks Safari and Firefox versions); `KHR_texture_basisu` needs the KTX2Loader, which is not ported (without a loader an optional extension falls back to the texture's own source and a required one throws, as upstream; with one set it throws); WebP and AVIF images decode through the platform (Flutter's decoder handles WebP; AVIF depends on the platform's codecs); lines and points take a `LineBasicMaterial`/`PointsMaterial` whose base properties are copied by a function repeating `Material.copy`'s list (upstream calls `Material.prototype.copy` on them; Dart cannot call a superclass method on another class's instance). Part 3 (B5c): a CUBICSPLINE track gets its interpolant through `KeyframeTrack.interpolantFactory` (E-FACTORY) in place of an assigned `track.createInterpolant`, without the `isInterpolantFactoryMethodGLTFCubicSpline` marker (`getInterpolation()` returns `null` for it, as upstream's `undefined`); `loadSkin` has no "Joint could not be found" warning, since a joint node always loads as a `Bone`; a clip's unset duration is `-1` (upstream passes `undefined`). `crossOrigin` has no effect beyond `use-credentials` (it sends credentials, as upstream's FileLoader setting); `setDRACOLoader`, `setKTX2Loader` and `setMeshoptDecoder` store their argument, and the extensions that need them are not registered. Tested in `packages/ent/test/loaders/gltf_loader_test.dart` against r187 loading the same files in Node (images by size and a hash of their bytes: Node has no image decoder), and by the `gltf_meshes`, `gltf_textured` and `gltf_skinned_anim` reference scenes | Dart has futures, not promises, and no duck typing; there is no CORS outside a browser |
| E-POSTPROCESSING | `EffectComposer` and its passes draw `ShaderMaterial`s and `RawShaderMaterial`s whose GLSL `WebGLRenderer` compiles at runtime (with the material's `defines`); passes call the renderer itself (`renderer.clear`, `autoClear*`, `getContext()` and `state.buffers.stencil` for masks) | Each effect is an `EffectMaterial` of ent with typed settings and no shader code (`CopyMaterial`, `OutputMaterial`, `VignetteMaterial`, `FXAAMaterial`, and `TuningPass`'s `HighPassMaterial`, `BlurMaterial` and `BloomMaterial`); its shader is the renderer's: `FlutterGpuRenderer` keeps a precompiled program per material class (E-SHADERS: GLSL 4.60 for impellerc, written by hand after the reference's shaders), filled from the material's fields (the reference's defines become uniforms: the five blur kernels, 3 to 11 tap pairs, are one program whose loop is bounded by a uniform, its offsets and weights packed in vec4 arrays). There are no shader definitions (`ShaderDefinition`, the reference's `CopyShader` and the others) and no `ShaderPass`: an `EffectPass` draws an effect material over its target, `CopyPass` and `VignettePass` standing for the reference's ShaderPass of CopyShader and VignetteShader. ## Migration notes

- `for ( const c of v )` → `for (final c in v.iterable)`; `[ ...v ]` → `v.iterable.toList()`.
- `v.set( i, j )` with `int` variables → `v.set(i.toDouble(), j.toDouble())`.
- `try { … } catch ( e ) { e.message }` → `on EntError catch (e) { e.message }`.
- `setConsoleFunction( ( type, message, ...params ) => … )` → `setConsoleFunction((type, message, params) { … })`.
- `if ( object.isEuler )` on a value of unknown type → `if (object is Euler)`.
- `THREE.Triangle.getNormal( a, b, c, target )` → `Triangle.getNormalStatic(a, b, c, target)`.
- `color.getHSL( {} )` → `color.getHSL(HSL())`; `box.toJSON().min` → `box.toJSON()['min']`.
- `obj.addEventListener( 'added', function ( e ) { this… } )` → `obj.addEventListener('added', (e) { e.target… })`;
  `dispatchEvent( { type: 'x', value: 1 } )` → `dispatchEvent(Event('x', {'value': 1}))`.
- `parent.add( a, b )` → `parent..add(a)..add(b)`.
- `geometry.groups[ 0 ].materialIndex`, `camera.view.offsetX`, `hit.distance`: same names on the Dart classes.

## Upstream behaviour reproduced on purpose

The port follows r187 even where its behaviour looks unintended; each case is pinned by a test so a
deliberate change shows up.

- `CubeCamera.updateCoordinateSystem` removes its six cameras before validating the coordinate system, so an
  invalid call leaves it empty.
- `StereoCamera` eye-offset matrices are module-level: a cache hit returns the offset of whichever stereo
  camera last recomputed.
- `CubeDepthTexture.copy/clone` turns the six faces into an object keyed `'0'`..`'5'` (`Object.assign({}, array)`).
- Replaying an action after `AnimationMixer.uncacheClip` of a clip sharing a binding throws (stale `_cacheIndex`).
- `SpotLight.toJSON()` at the root does not add its `map` to `textures` (the caller's `meta` is undefined).
- `QuaternionLinearInterpolant` with a stride of 8 writes only `result[0..3]`.
